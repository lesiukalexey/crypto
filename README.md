# Bitget Price Tracker

Локальный сборщик публичных котировок Bitget. Он периодически получает лучшие цены спроса и предложения для заданных тикеров и записывает историю в отдельную базу MySQL `bitget_quotes`.

- `bid_price` — лучшая заявка покупателя; если продавать сразу, исполнение ориентируется на bid.
- `ask_price` — лучшая заявка продавца; если покупать сразу, исполнение ориентируется на ask.
- Ключ Bitget не нужен: используется публичный market-data API.
- Цены сохраняются как текст, без преобразования в float.
- Приложение само создает таблицу `quote_snapshots` в выбранной схеме.

## Настройка MySQL

Создайте отдельную схему в MySQL:

```sql
CREATE DATABASE bitget_quotes CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

В `config.json` задайте `host`, `port`, `user` и имя базы. Для проекта выделены пользователь `bitget_quote_collector` и отдельная схема `bitget_quotes`. Пользователю MySQL достаточно прав на эту схему. Пароль передается через `BITGET_DB_PASSWORD` и хранится вне репозитория.

## Настройка тикеров

Отредактируйте `config.json`:

```json
{
  "category": "USDT-FUTURES",
  "symbols": ["BTCUSDT", "ETHUSDT"],
  "poll_interval_seconds": 5,
  "request_timeout_seconds": 10,
  "mysql": {
    "host": "127.0.0.1",
    "port": 3306,
    "user": "bitget_quote_collector",
    "password_env": "BITGET_DB_PASSWORD",
    "database": "bitget_quotes",
    "connect_timeout_seconds": 5
  }
}
```

Поддерживаемые категории Bitget: `SPOT`, `USDT-FUTURES`, `COIN-FUTURES`, `USDC-FUTURES`. Интервал опроса задается в секундах. В текущем конфиге указаны ваши пары и интервал 60 секунд; все шесть пар проверены в категории `USDT-FUTURES`.

За один запрос получаются котировки рынка выбранной категории, затем сохраняются только заданные пары. Частота регулируется `poll_interval_seconds`; каждая строка содержит время получения в UTC и timestamp Bitget. Таблица хранит неизменяемые снимки, а не только последнюю цену.

## Запуск

Нужен Python 3.10+ и доступная MySQL база. Установите зависимость и задайте пароль в окружении:

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
export BITGET_DB_PASSWORD='ваш-пароль'
python app.py
```

## Автозапуск при старте компьютера

Для Linux с systemd подготовлен пользовательский unit `systemd/bitget-price-tracker.service`. Создайте защищенный env-файл с паролем MySQL:

```bash
mkdir -p ~/.ai/home/.local
nano ~/.ai/home/.local/bitget-price-tracker.env
chmod 600 ~/.ai/home/.local/bitget-price-tracker.env
```

В файле должна быть строка `BITGET_DB_PASSWORD=пароль-пользователя-bitget_quote_collector`. По умолчанию служба подключается к MySQL, доступному на `127.0.0.1:3306`; измените `host` и `port` в `config.json`, если сервер расположен в другом месте. Затем установите и включите службу:

```bash
mkdir -p ~/.config/systemd/user
ln -sf /var/www/bitget/systemd/bitget-price-tracker.service ~/.config/systemd/user/bitget-price-tracker.service
systemctl --user daemon-reload
systemctl --user enable --now bitget-price-tracker.service
```

Если служба уже включена, но вы только что создали env-файл, запустите ее один раз:

```bash
systemctl --user start bitget-price-tracker.service
```

На этой машине user-service включен в автозапуск. Чтобы просмотреть состояние и журнал:

```bash
systemctl --user status bitget-price-tracker.service
journalctl --user -u bitget-price-tracker.service -f
```

Служба ожидает этот env-файл, поэтому до добавления пароля она пропускает запуск. При недоступности MySQL после запуска systemd перезапускает сборщик. Установка сборщика не устанавливает сам MySQL-сервер.

Для одного запроса и завершения:

```bash
python app.py --once
```

Остановить непрерывный сбор можно `Ctrl+C`. Путь к конфигу задается через `--config /path/to/config.json`.

## Просмотр последних записей

```sql
SELECT category, symbol, bid_price, ask_price, received_at_utc
FROM quote_snapshots
ORDER BY id DESC
LIMIT 20;
```

На следующем этапе бэктестер сможет повторно использовать эти же снимки для сравнения стратегий. При расчете исполнения нужно учитывать покупку по ask, продажу по bid и комиссию отдельно на каждой стороне сделки. Для фьючерсов также потребуются правила размера контракта, плеча и funding.

## График котировок

Локальная PHP-страница показывает сохраненные `bid`, `ask` и `last` для выбранной пары и диапазона дат. В фильтрах можно задать начальную и конечную даты; обе границы включаются, даты трактуются по часовому поясу `Europe/Kyiv`. Наведите курсор на график, чтобы увидеть ближайший снимок и точные сохраненные значения всех трех цен; время отображается по Киеву.

Под графиком выполняется симуляция на тех же котировках. Начальный баланс по умолчанию — 10 USDT; комиссия market/taker по умолчанию — 0.06% за сторону. `entry_profiles.json` и `exit_profiles.json` задают исходные наборы порогов входа, окон снимков и диапазонов Take Profit / Stop Loss. На странице в блоке «Параметры расчёта» задаются отдельные пороги и окна снимков для трёх режимов: симметричный ± (long при росте и short при падении), только рост + (long) и только падение − (short). Для каждого режима можно выбрать текущий набор или свой диапазон «от / до / шаг». Отдельно настраиваются фиксированные TP и SL и варианты только TP или только SL. Исходные пороги входа неравномерны, поэтому они сохраняются как точный набор в режиме «Текущие значения». Применённые параметры передаются обоим видам рейтинга и входят в ключ кэша. Для немедленного входа открывается одна позиция по первому снимку периода, повторных входов нет. В рейтингах остаются только варианты выхода, давшие минимум две сделки; пороги входа ранжируются по лучшему результату среди этих вариантов. Автоматические варианты сортируются по чистому результату; в каждой группе отображаются до 500 лучших сочетаний. Рейтинг считается фоновой задачей и кэшируется для выбранных параметров. Кнопка рядом с торговой парой сбрасывает кэш рейтингов всех пар и запускает новый расчет только для выбранного тикера; кнопка в блоке общего рейтинга отдельно запускает расчет по всем тикерам. После закрытия позиции стратегия по импульсу ждет нового пересечения; если выходной порог не сработал, открытая позиция закрывается по последнему снимку выбранного периода. В журнале показаны комиссии, чистый результат и баланс после сделки. Подробнее — в [описании стратегии](http://127.0.0.1:18083/strategies.php).

Это упрощенный расчет с плечом 1× и дробным количеством. Он не учитывает биржевый шаг лота, funding, ликвидацию и пересечение порога между минутными снимками; фактический результат может превысить заданный порог фиксации. Комиссия зависит от тарифа аккаунта; Bitget указывает стандартную ставку taker 0.06% для USDT-Futures ([Bitget Futures](https://www.bitget.com/futures/)).

Откройте в браузере: <http://127.0.0.1:18083/>. Страница читает только сохраненную таблицу `quote_snapshots` и запускается пользовательской службой `bitget-price-chart.service` вместе с автоматическим входом пользователя.

```bash
systemctl --user status bitget-price-chart.service
journalctl --user -u bitget-price-chart.service -f
systemctl --user restart bitget-price-chart.service
```
