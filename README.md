# Bitget Price Tracker

Локальный сборщик публичных котировок Bitget. Он периодически получает лучшие цены спроса и предложения для заданных тикеров и записывает историю в отдельную базу MySQL `bitget_quotes`.

- `bid_price` — лучшая заявка покупателя; если продавать сразу, исполнение ориентируется на bid.
- `ask_price` — лучшая заявка продавца; если покупать сразу, исполнение ориентируется на ask.
- Ключ Bitget не нужен: используется публичный market-data API.
- Цены сохраняются как текст, без преобразования в float.
- Приложение само создает таблицу `quote_snapshots` в выбранной схеме.

## Настройка MySQL

Создайте отдельную схему в MySQL:

```sql
CREATE DATABASE bitget_quotes CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

В `config.json` задайте `host`, `port`, `user` и имя базы. Для проекта выделены пользователь `bitget_quote_collector` и отдельная схема `bitget_quotes`. Пользователю MySQL достаточно прав на эту схему. Пароль передается через `BITGET_DB_PASSWORD` и хранится вне репозитория.

## Настройка тикеров

Отредактируйте `config.json`:

```json
{
  "category": "USDT-FUTURES",
  "symbols": ["BTCUSDT", "ETHUSDT"],
  "poll_interval_seconds": 5,
  "request_timeout_seconds": 10,
  "mysql": {
    "host": "127.0.0.1",
    "port": 3306,
    "user": "bitget_quote_collector",
    "password_env": "BITGET_DB_PASSWORD",
    "database": "bitget_quotes",
    "connect_timeout_seconds": 5
  }
}
```

Поддерживаемые категории Bitget: `SPOT`, `USDT-FUTURES`, `COIN-FUTURES`, `USDC-FUTURES`. Интервал опроса задается в секундах. В текущем конфиге указаны ваши пары и интервал 60 секунд; все шесть пар проверены в категории `USDT-FUTURES`.

За один запрос получаются котировки рынка выбранной категории, затем сохраняются только заданные пары. Частота регулируется `poll_interval_seconds`; каждая строка содержит время получения в UTC и timestamp Bitget. Таблица хранит неизменяемые снимки, а не только последнюю цену.

На странице «Настройки» раздел «Списки тикеров» позволяет создавать именованные списки и добавлять в них пары по одной; раздел «Активные тикеры» управляет участием пар в расчётах. «Базовый список» содержит все активные пары на момент первоначального создания. Данные списков хранятся отдельно в `~/.ai/home/.local/bitget-quote-sets.json`.

## Запуск

Нужен Python 3.10+ и доступная MySQL база. Установите зависимость и задайте пароль в окружении:

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
export BITGET_DB_PASSWORD='ваш-пароль'
python app.py
```

Обычный рейтинг и мартингейл выполняются через Numba с JIT-компиляцией при первом запуске; отдельная сборка C++-расширения не нужна.

Обычный рейтинг тикера и общий рейтинг сохраняют сжатые состояния симуляций по
выбранной конечной дате в `~/.ai/home/.local/bitget-simulation-checkpoints/`,
отдельно от БД и сбрасываемого кнопкой 🧹 кэша. Повторный запрос за тот же
период использует готовые состояния, а прерванный расчёт достраивает только
отсутствующие варианты. Для более поздней конечной даты расчёт продолжается с
последнего подходящего состояния; прежняя дата сохраняется. Параметры и SHA-256
префикса котировок проверяются перед повторным использованием. Готовый итог
общего рейтинга хранится там же и проверяется по содержимому котировок при
каждом повторном запросе. Открытая позиция по-прежнему оценивается на последнем
снимке периода. При свободном месте меньше 1 ГиБ запись новых состояний
приостанавливается, а рейтинг завершается.

## Автозапуск при старте компьютера

Для Linux с systemd подготовлен пользовательский unit `systemd/bitget-price-tracker.service`. Создайте защищенный env-файл с паролем MySQL:

```bash
mkdir -p ~/.ai/home/.local
nano ~/.ai/home/.local/bitget-price-tracker.env
chmod 600 ~/.ai/home/.local/bitget-price-tracker.env
```

В файле должна быть строка `BITGET_DB_PASSWORD=пароль-пользователя-bitget_quote_collector`. По умолчанию служба подключается к MySQL, доступному на `127.0.0.1:3306`; измените `host` и `port` в `config.json`, если сервер расположен в другом месте. Затем установите и включите службу:

```bash
mkdir -p ~/.config/systemd/user
ln -sf /var/www/bitget/systemd/bitget-price-tracker.service ~/.config/systemd/user/bitget-price-tracker.service
systemctl --user daemon-reload
systemctl --user enable --now bitget-price-tracker.service
```

Если служба уже включена, но вы только что создали env-файл, запустите ее один раз:

```bash
systemctl --user start bitget-price-tracker.service
```

На этой машине сборщик остановлен и отключён в автозапуске. Команды `enable --now` выше снова включат его, если это понадобится. Чтобы просмотреть состояние и журнал:

```bash
systemctl --user status bitget-price-tracker.service
journalctl --user -u bitget-price-tracker.service -f
```

Служба ожидает этот env-файл, поэтому до добавления пароля она пропускает запуск. При недоступности MySQL после запуска systemd перезапускает сборщик. Установка сборщика не устанавливает сам MySQL-сервер.

Для одного запроса и завершения:

```bash
python app.py --once
```

## Исторические минутные свечи

Историю можно загрузить из Bitget отдельно от снимков Bid/Ask: свечи сохраняются в
`historical_candles` с OHLC и объёмом. Импорт использует шаг `1m`, загружает
полный выбранный диапазон календарных дат `Europe/Kyiv` до последней завершённой
минуты, включая уже архивированные минуты для восстановления пропусков. В
`quote_snapshots` добавляются только минуты без существующей котировки; реальные
снимки не заменяются. Для добавленных исторических минут Close свечи используется
как прокси Bid/Ask/Last и помечается `historical_candle_close`.

```bash
python3 import_historical_candles.py --symbol ETHUSDT --start-date 2026-10-01 --end-date 2026-10-10
python3 import_historical_candles.py --all-enabled --start-date 2026-10-01 --end-date 2026-10-10
```

На главной странице кнопки `↻ <пара>` и `↻ Все активные пары` запускают тот же
импорт в фоне по выбранному диапазону и показывают прогресс. После загрузки срез
расчётов обновляется, график и таблица перечитываются. «Активные» пары берутся из
включённых тикеров на странице «Настройки». Исторические свечи не содержат
настоящие Bid и Ask, поэтому цены Close в симуляции являются приближением.

Кнопка «Последняя котировка» в шапке продолжает импорт для всех активных пар: для
каждой пары отдельно берётся её последняя сохранённая минута, затем запрашиваются
свечи до последней завершённой минуты Bitget. Уже существующие снимки котировок не
заменяются.

Остановить непрерывный сбор можно `Ctrl+C`. Путь к конфигу задается через `--config /path/to/config.json`.

## Просмотр последних записей

```sql
SELECT category, symbol, bid_price, ask_price, received_at_utc
FROM quote_snapshots
ORDER BY id DESC
LIMIT 20;
```

На следующем этапе бэктестер сможет повторно использовать эти же снимки для сравнения стратегий. При расчете исполнения нужно учитывать покупку по ask, продажу по bid и комиссию отдельно на каждой стороне сделки. Для фьючерсов также потребуются правила размера контракта, плеча и funding.

## График котировок

Локальная PHP-страница показывает сохраненные `bid`, `ask` и `last` для выбранной пары и диапазона дат. В фильтрах можно задать начальную и конечную даты; обе границы включаются, даты трактуются по часовому поясу `Europe/Kyiv`. Наведите курсор на график, чтобы увидеть ближайший снимок и точные сохраненные значения всех трех цен; время отображается по Киеву.

Под графиком выполняется симуляция на тех же котировках. Начальный баланс по умолчанию — 10 USDT; комиссия market/taker по умолчанию — 0.06% за сторону. Обычная позиция каждый раз открывается номиналом от стартового баланса, а не от накопленного после предыдущих сделок; прибыль и убыток не меняют размер следующей обычной позиции. `entry_profiles.json` задаёт пороги входа в процентах от стартового баланса и окна снимков, а `exit_profiles.json` задаёт диапазоны Take Profit / Stop Loss. При позиции номиналом около всего баланса и плече 1× порог доходности соответствует сопоставимому процентному движению Last. TP/SL задаются процентом от стартового баланса: шаг 0,1% соответствует 0,01 USDT при старте с 10 USDT; денежная цель фиксирована относительно начального депозита при изменении накопленного баланса. На странице в блоке «Параметры расчёта» задаётся общий набор порогов входа в процентах от стартового баланса и единый диапазон «от / до / шаг» для симметричного ±, роста + и падения −. Один набор окон снимков также общий для всех трёх режимов; можно выбрать текущий набор или один общий диапазон. Отдельно настраиваются фиксированные TP и SL и варианты только TP или только SL в процентах от стартового баланса. Исходные пороги входа неравномерны, поэтому они сохраняются как точный набор в режиме «Текущие значения». Применённые параметры передаются обоим видам рейтинга и входят в ключ кэша. Для немедленного входа открывается одна позиция по первому снимку периода, повторных входов нет. В SAVE MODE в рейтингах остаются только варианты выхода, давшие минимум три сделки; при отключенном SAVE MODE достаточно одной сделки; пороги входа ранжируются по лучшему результату среди этих вариантов. Автоматические варианты сортируются по чистому результату; в каждой группе отображаются до 500 лучших сочетаний. Рейтинг считается фоновой задачей и кэшируется для выбранных параметров. Кнопка рядом с торговой парой сбрасывает кэш рейтингов всех пар и запускает новый расчет только для выбранного тикера; кнопка в блоке общего рейтинга отдельно запускает расчет по всем тикерам. В глобальном топе и таблице лучших комбинаций тикеров нажмите на порог входа или TakeProfit & StopLoss, чтобы открыть в новой вкладке таблицу результата этой же пары для всех тикеров: порог и TP/SL будут одинаковыми в каждой строке, а «Итог тикера» покажет прибыль или убыток по выбранным котировкам. После закрытия позиции стратегия по импульсу ждет нового пересечения; если выходной порог не сработал, открытая позиция закрывается по последнему снимку выбранного периода. В журнале показаны комиссии, чистый результат и баланс после сделки. Подробнее — в [описании стратегии](http://127.0.0.1:18083/strategies.php).

Это упрощенный расчет с плечом 1×. В мартингейле текущие публичные правила контракта Bitget применяются к каждому рыночному ордеру: минимальная сумма и количество, шаг/точность количества, максимум рыночного ордера и доступный баланс с комиссией. Правила загружаются из Bitget и кэшируются на час; к историческим котировкам применяются текущие правила, поскольку архив правил контракта не ведется. Обычный режим пока использует дробное количество без округления по шагу контракта. Модель не учитывает funding, ликвидацию, частичное исполнение и движение цены между минутными снимками; фактический результат может превысить заданный порог фиксации. Комиссия зависит от тарифа аккаунта; ставка задается в настройках расчета. [Bitget Contract Configuration](https://www.bitget.com/docs/catalog/classic-contract-market/classic-contract-market).

Откройте в браузере: <http://127.0.0.1:18083/>. Страница читает только сохраненную таблицу `quote_snapshots` и запускается пользовательской службой `bitget-price-chart.service` вместе с автоматическим входом пользователя.

```bash
systemctl --user status bitget-price-chart.service
journalctl --user -u bitget-price-chart.service -f
systemctl --user restart bitget-price-chart.service
```
